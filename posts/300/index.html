大模型和Agent

大模型和Agent区别

  • 常规 LLM（如网页版 ChatGPT）： 是一问一答的无状态（Stateless）函数。它是被动的，你输入一段 Prompt，它输出一段文本，交互到此结束。

  • Agent： 是一个有状态（Stateful）的闭环系统。它具备三个核心组件：记忆（Memory）、工具（Tools/APIs）和规划能力（Planning）。你只需给 Agent 设定一个“宏大目标”，它会自动将任务拆解，自主调用工具执行，观察结果。如果出错，它会利用大模型的能力分析报错并自我纠错，直到完成目标。

为什么常规 LLM 搞不定多文件重构？Code Agent 怎么解决？

原因在于上下文物理限制和文件拓扑结构的缺失。让大模型一次性吞下多个文件，不仅容易超出 Token 限制，还会导致模型产生“注意力遗忘”（Lost in the Middle）。

最近很火的 Code Agent（例如 Claude Code、Cursor、Cline、Aider 等）正是为了解决这个痛点而生，它们的使用方式与常规 LLM 有天壤之别：

  • 主动的环境感知 (Workspace Awareness)：
    你不再需要手动复制粘贴代码。Code Agent 直接集成在终端（CLI）或 IDE（如 VS Code）中。当你让它“重构数据加载模块”时，Agent 会自己执行 grep 搜索、读取目录树、寻找依赖项，主动把需要的文件拉入上下文。

  • 读写执行一体化 (Action Execution)：
    常规 LLM 只能生成代码文本让你去复制；Code Agent 可以直接通过文件系统 API 修改、保存文件。

  • 自主纠错循环 (Self-Correction Loop)：
    这是 Agent 最核心的优势。如果你让 Agent 重构一个类，重构后运行报错了，Agent 会自动捕获 Terminal 里的 Traceback，把错误信息发回给大模型分析，重新生成补丁，再次运行，循环往复，直到代码能成功跑通。你在这个过程中不需要说话，只需看着它干活。

常规大模型做不好、必须要 Agent 上的 3 个科研场景

常规大模型最怕“长程链路”和“需要实时验证”的任务。以下三个场景是 Agent 的绝对主场：

  1. 深度追踪与复现最新的 Baseline (Paper & Code Exploration)

  • 大模型的劣势： 你把 2026 年最新时序顶会论文的 PDF 或 GitHub 链接丢给大模型，让它解释某个核心公式的工程实现。它只能“盲猜”，因为看不到代码全貌，更无法运行。

  • Agent 的优势： 像 Claude Code 或 Cline 这样的开发 Agent，你可以直接给它一个 GitHub 存储库的 URL。它会自主下载代码、阅读目录树、使用 grep 查找关键的模块（比如查找哪些文件实现了频率域的 Mask 操作），甚至可以尝试在你的服务器环境中运行 pip install 搭建环境，编译报错了它自己去改 setup.py。

  • 价值： 帮你用最短的时间把别人的 Baseline 在你的服务器上跑通。

  1. 多文件联动下的复杂模型架构调整 (Cross-File Code Refactoring)

  • 大模型的劣势： 正如你之前所说，你只敢传单个 model.py。如果你想把 RouteTS 的核心机制从“通道独立（Channel-Independent）”改成“通道混叠（Channel-Mixing）”，这不仅要改模型层，还要改 data_provider.py 的数据对齐、exp_basic.py 的训练流程。单文件传给大模型，它改完必报维度错误（Shape Mismatch）。

  • Agent 的优势： 给 Workspace Agent 权限，它会通盘阅读这 3 个相关文件。它在修改 model.py 时，会同步自动修改 data_provider.py 的维度，甚至在终端自动运行一下 python main.py —dry_run=True 来验证张量在 Forward 过程中会不会挂掉。

  • 价值： 它拥有“全局观”和“动态调试能力”，这是单文件复制粘贴绝对做不到的。

  1. 文献网络深度调研 (Autonomous Literature Review)

  • 大模型的劣势： 只能基于它已有的知识，或者你喂给它的单篇 PDF 进行解答，无法顺藤摸瓜。

  • Agent 的优势： 比如科研专用 Agent（如 Perplexity Pro 的深度搜索模式，或开源的 Auto-Research Agent）。你输入：“追踪 2025-2026 年间，所有将 Transformer 的 Attention 机制应用在三维时序预测上的 CCF-A 级论文”。Agent 会在后台自动去 arXiv、Semantic Scholar 上检索，下载前 5 篇，阅读其 Related Work，顺着引用文献（Citation Tree）再下载 10 篇，最后给你整理出一份包含方法对比、Baseline 使用情况的深度报告。

  • 价值： 代替你做连续几小时的“找文献-下文献-看摘要”的机械劳动。

推荐的Agent

考虑到你使用 VS Code Remote SSH 访问远程服务器的习惯，你的 Agent 部署策略应该因地制宜：

  1. 代码开发类：推荐“本地操作、远程生效”的混合模式
    你不需要在服务器上装复杂的图形化 Agent。

  • 首选方案：Cursor 或 VS Code + Cline 插件（本地部署，API 远程连接）

    • 怎么用： 它们装在你的本地电脑（Mac/Windows）上，但因为你的 VS Code 已经通过 SSH 连接了服务器，这些 Agent 插件可以直接感知并操作你远程服务器上的工作区文件。

    • 模型选择： 强烈建议接入 Claude 3.5 Sonnet (API)。在逻辑推理、复杂代码编写和多文件重构上，它是目前学术界和工业界公认断层第一的模型。

    • 特点： 这属于 Local-Agent (Controlled Actions)。它每次改你服务器上的代码、或者想在服务器终端运行命令时，都会在本地弹窗询问你：“我是否可以修改 exp_model.py？”、“我是否可以运行 python main.py？”。对博士生来说非常安全，完全在你的掌控之中。

  1. 文献调研与 Idea 验证类：推荐“云端/远程 Agent”

  • 首选方案：Perplexity (Pro 模式) 或 Consensus

  • 怎么用： 直接在网页端使用。不需要本地任何环境，直接利用它们后台庞大的网络爬虫和学术数据库检索能力。

  • 特点： 适合在你每天早上开启科研工作前，或者和导师 regular meeting 前，用来快速摸清某个细分 idea 是否已经被别人做过。

正则化技巧

有时候在markdown里面，会把一级标题被我设置为了##, 二级标题被我设置为了###，最高到####。

现在希望让所有的标题都缩减一级，也就是##变为#。可以直接用正则表达式一步到位。

  1. 打开替换面板：按 Ctrl+H（Windows/Linux）或 Cmd+Option+F（Mac）
  2. 开启正则模式：点击替换面板右上角的 .* 按钮（或按快捷键 Alt+R）
  3. 查找框输入：
    ^(#+)# (.*)
  4. 替换框输入：
    $1 $2
    原理说明：
  • ^：匹配每一行的开头，确保只处理行首的标题，不会误改正文里的#号
  • (#+)#：先捕获连续的 N 个#到分组$1，再匹配第 N+1 个#；整体只匹配「至少 2 个 #」的标题，替换后自然减少一个#
  • (.*)：匹配标题后的空格和全部标题内容，$2 对应原标题文字
  • 最终替换为 $1 $2，就是「N 个# + 空格 + 原标题内容」，正好降级一级

matplotlib绘图以适应latex排版

学术投稿一般都是latex，但是有些图是需要用matplotlib绘图，但是过往绘制出来的图，放到latex里面，会出现图片过大或过小的问题，之前我都是使用width=0.85\textwidth进行缩放，但是这就其实不好，会导致图片中的所有元素（线条、颜色、文字）都被一起缩放，在生成的pdf里面看起来就很奇怪。所以解决办法是：永远在绘图时就确定最终物理尺寸。

一旦确定了画布宽度，就永远不要在 LaTeX 中对图片进行任何缩放。

为了解决这个问题，可以依靠tueplots来帮助我们解决这个问题，针对ICLR排版（其他顶会也有），自动调整图片的宽度/字体大小等。

  • 精准提取布局参数： 直接阅读我的草稿代码（例如 fig, axes = plt.subplots(...)），从中精确提取行数（nrows）和列数（ncols）。
  • 精准提取子图数量： 统计我实际绘制了几个子图（N）。
  1. 第二原则：正确应用 tueplots 样式工具
  • 必须在代码最开头调用 apply_iclr_global_style(nrows=nrows, ncols=ncols, rel_width=1.0)，参数使用上一原则中提取的数值。

  • 数据绘制完成后，必须调用 format_academic_axes(axes) 统一美化所有子图。
  • 坐标轴标签（xlabel, ylabel）必须使用 fontweight='bold'。
  • 图例规范配置：
  • 若为单个子图图例，请使用 setup_academic_legend(ax, **kwargs) 进行配置。
  • 若为多子图合并的全局图例，请直接调用封装好的 setup_global_academic_legend(fig, axes) 自动提取标签并渲染，确保其不遮挡数据走势。

iclr_style.py 参考实现：

import matplotlib.pyplot as plt
import numpy as np
from tueplots import bundles

def apply_iclr_global_style(nrows, ncols, rel_width=1.0):
    plt.rcParams.update(bundles.iclr2024(rel_width=rel_width, nrows=nrows, ncols=ncols))
    plt.rcParams['pdf.fonttype'] = 42
    plt.rcParams['ps.fonttype'] = 42

def format_academic_axes(axes):
    if not isinstance(axes, (list, np.ndarray)):
        axes_list = [axes]
    else:
        axes_list = np.array(axes).flatten()

    for ax in axes_list:
        if not ax.get_visible():
            continue
            
        ax.spines['top'].set_visible(True)
        ax.spines['right'].set_visible(True)
        ax.spines['left'].set_linewidth(1.2)
        ax.spines['right'].set_linewidth(1.2)
        ax.spines['top'].set_linewidth(1.2)
        ax.spines['bottom'].set_linewidth(1.2)

        ax.tick_params(axis='both', which='major', direction='out')
        ax.grid(True, linestyle=':', alpha=0.5)

        for label in ax.get_xticklabels() + ax.get_yticklabels():
            label.set_fontweight('bold')

def hide_empty_subplots(axes, n_active):
    if isinstance(axes, (list, np.ndarray)):
        axes_flat = np.array(axes).flatten()
        for i in range(n_active, len(axes_flat)):
            axes_flat[i].set_visible(False)

def setup_academic_legend(ax, **kwargs):
    default_kwargs = {
        'loc': 'lower center',
        'bbox_to_anchor': (0.5, 1.02),
        'frameon': True,
        'facecolor': 'white',
        'edgecolor': 'lightgray'
    }
    default_kwargs.update(kwargs)
    ax.legend(**default_kwargs)

def setup_global_academic_legend(fig, axes, **kwargs):
    axes_flat = np.array(axes).flatten()
    handles, labels = [], []
    for ax in axes_flat:
        h, l = ax.get_legend_handles_labels()
        for hi, li in zip(h, l):
            if li not in labels:
                handles.append(hi)
                labels.append(li)
                
    default_kwargs = {
        'loc': 'upper center',
        'bbox_to_anchor': (0.5, 1.1),
        'ncol': min(len(labels), 3),
        'frameon': True,
        'facecolor': 'white',
        'edgecolor': 'lightgray'
    }
    default_kwargs.update(kwargs)
    fig.legend(handles, labels, **default_kwargs)

zotero同步

背景

原文链接

zotero同步分为两种：
数据同步和文件同步

数据同步：数据同步内容可以包含文献库的条目、笔记、链接、标签等等。在Zotero中，可以使用Zotero提供的同步服务同步除了附件之外的所有内容，以便在不同的支持Zotero的设备上使用Zotero。英文版内容为：[library items, notes, links, tags, etc.—everything except attachment files]。此外，还可以登录 Zotero.org 在线查看文献库。数据同步是免费和无限的，无需文件同步即可使用。

文件同步：数据同步将同步库项目，但不同步附件（PDF，音频和视频文件，图像等）。官方提供的网盘只有300M，PDF多了后肯定不够用

解决思路

原链接

核心思路：把题录数据和附件分开存储

实际操作

在不同的电脑做好以下操作：

  1. 安装zotero软件、zotfile插件、茉莉花插件

  2. zotero账号注册，同步设置。看下图，有一个框不要勾选

  3. 网盘同步（可以使用坚果云、百度网盘、onedrive等）。我是用的是onedrive，只需要在onedrive中新建一个文件夹来存放pdf文件

  4. 找到zotFile首选项，把上一步设置的文件夹位置填进去，下面的子文件夹命名方式表示作者的姓氏（详细的可以去查一下）

  1. 找到[首选项]->[高级]->[文件和文件夹]，把根目录的路径设置为上面的路径，这一步是为了让你的zotero知道附件存储在哪

  2. 将文件移动到网盘，zotero里面只用剩一个链接。可以看到移动后，pdf文件图标左下角有一个链接的图案

  1. 其他设备使用，进入zotero后，点击右边的绿色同步按钮，等待即可

zotero 抓取参考文献

我自己目前大概总结出来了一套方法，以后如果要把论文导入进去，要确保参考文献不出错的情况下，那么首先要保证这个论文的条目信息没有错误，右键-》生成条目报告，就能看到相关信息，就能知道这个这个论文却不缺少内容。

然后，因为只传入pdf，然后自动抓取，一般会缺少很多信息。所以，最好的方法是使用bibtex，次选方法是doi。因为有的论文还没有doi。

关于bibtex，可以不用去官网看，因为有可能会比较慢。如果要批量导入，那么直接浏览器搜索：bibtex 论文名称。 这个时候ai可能会为你查找到bibtex，不过有的可能用的是arxiv的，这个时候可能需要自己去官网下载。然后把多篇论文的bibtex复制到一个bib文件，然后直接导入。这个时候批量生成了条目，然后全选+右键，查找全文，就能获取pdf。但是这个时候，有的可能没找到pdf，原因大概率是bibtex有问题，缺少了url链接。或者这个论文是IEEE等网站，没法直接下载。如果是缺少了链接，那么就去官网找bibtex就好了；如果是IEEE，那需要单独下载pdf，手动添加。

远程服务器实验记录方案

一般实验是在远程服务器上面进行，所有的数据一般也是在服务器上面被记录。但是为了更好的进行对比，需要将其整理到excel里面。之前的做好是手动在本地构建excel表格，然后把服务器上面的数据复制过来，但是效率非常低。

后面思考了下，可以这样去做，来提高效率：

核心方案在远程服务器上维护一个 experiment_log.csv

设计格式可以参考：

timestamp,dataset,model,pred_len,lr,mse,mae,notes,log_path
2026-07-11 10:00,ETTh1,LSTM,12,0.001,0.452,0.318,baseline,logs/exp_001.log
2026-07-11 10:30,ETTh1,MyModel,12,0.001,0.381,0.285,加了注意力,logs/exp_002.log
2026-07-11 11:00,ETTh1,MyModel,24,0.001,0.402,0.298,调大dropout,logs/exp_003.log

我个人觉得，这个excel表格可以多设计几个，以免弄混淆。例如，Baseline、论文方法多版本对比、各类消融实验

记录方法

  • 模式 A：手动记录

    • 跑完实验后，如果你觉得结果值得记录，在终端执行：python log_exp.py --dataset ETTh1 --model MyModel --pred_len 24 --mse 0.402 --mae 0.298 --notes "dropout=0.3"。这个log.py可以让大模型为我写，可以参考下面这个：
      import csv, datetime, argparse, os

def main():
    parser = argparse.ArgumentParser()
    parser.add_argument('--dataset', required=True)
    parser.add_argument('--model', required=True)
    parser.add_argument('--pred_len', type=int, required=True)
    parser.add_argument('--mse', type=float, required=True)
    parser.add_argument('--mae', type=float, required=True)
    parser.add_argument('--notes', default='')
    parser.add_argument('--log_path', default='')
    args = parser.parse_args()
    
    file_exists = os.path.exists('experiment_log.csv')
    with open('experiment_log.csv', 'a', newline='') as f:
        writer = csv.writer(f)
        if not file_exists:
            writer.writerow(['timestamp','dataset','model','pred_len','lr','mse','mae','notes','log_path'])
        writer.writerow([
            datetime.datetime.now().strftime('%Y-%m-%d %H:%M'),
            args.dataset, args.model, args.pred_len, 
            '0.001',  # 你可以再加参数，或者从config读取
            args.mse, args.mae, args.notes, args.log_path
        ])
    print("已记录到 experiment_log.csv")

if __name__ == '__main__':
    main()

  • 模式 C：自动记录最优结果

色温

色温：环境中客观存在的光源颜色（温度的颜色）

物体在不同温度下有不同的颜色，比如加热一个物体，会从红到黄到白到蓝。物体在不同温度产生的颜色成为色温，单位:K

K值越低，色温越暖（红色就是低色温，蓝色是高色温）。简单的口诀是：炉火纯青

白平衡

白平衡：人为控制的相机设置。根据环境的色温来校准相机的颜色，还原物体现实中的颜色。

因为白平衡的k值和色温是相反的，除非物体是白色，两者数值是相同的。否则应该是相反的，一个高，另一个低。

白平衡一般只能在冷暖色调上偏移，如果画面偏绿，就要用到色彩偏移，色彩偏移能够调整出不同风格的照片。（蓝绿色调小清新风格—左上、红绿色调港风—右上、蓝粉色调法式—左下、红粉色调—复古）

    • Introduction。一般包含的内容：交代研究内容（让读者知道你要做什么）-》阐述研究现状并总结不足（给读者一些研究背景的铺垫，并且带出挑战以及难点）-》提出解决的新思路（引出论文的解决思路或者说idea，可以再介绍这一思路要实现的困难）-》给出新方案的设计（前面提到了idea实现的困难，这部分就要说为了解决这个困难，准备怎么做。也就是较为详细的介绍idea的实现）-》总结并且强调论文的贡献。
      • 需要注意的是。上面这个只是一个例子，并不是说论文一定要按照这个来写。关键是逻辑流程，言之有理。很多论文容易犯的错误是逻辑断裂：前面总结了研究现状的不总，然后就直接说自己的方法，中间是割裂的。或者在引出idea之前的内容和实际的idea/做法对不上等
    • Related-work：核心逻辑是对相关工作进行较为全面的归纳总结，绝对不是流水账。Introducion中的研究现状是针对你前面提到的问题别人是怎么做的。而related work 是你提出的解决方法涉及到的研究方向的国内外研究现状。二者侧重点不同。而且，Related-work中提到的相关工作，也是实验里面baseline的主要来源。
    • Introduction和Related-work 是 论文里面具有强逻辑性的部分，里面提到的结论性话语，按理说都需要在实验章节给出对应的实验进行验证，这样才能做到逻辑闭环，前后呼应。如果缺乏了，可以作为一个缺点补充上。
  • 图表：图表是否设计的美观，字体大小是否过大或过小；图能否做到直接看图和图注就能明白得到一些重要的信息。有些图画的过于复杂，或者用了很多logo，这种大概率是AI写的。
  • 实验：实验的结果是否能支持文字中的结论，有些论文会出现实验结果和文字是不相符合的。
  • 因为我本人往往不是这个小领域的从业者。所以评审论文主要从：写作逻辑、图表美观、实验设计等方面进行评价。
  • 你在给我答案的时候，对于拿不准或不清楚的可以空着，等我来做决定。给出的审稿意见是英文的，要注意语法和时态一致。同时，给出的词一定要慎重些，尽量不要随意用过于极端的副词、形容词等。例如：to rigorous verification。rigorous这种词要慎用。
